# Claread Web Product

> **状态**：CURRENT ｜ **最后更新**：2026-07-14

## 产品任务

Claread Web 帮助中文用户把英文材料变成一段可以持续阅读、理解、回看和沉淀的阅读经历。它不是小程序放大版、资料后台，也不是把文章放在一侧的通用 AI 聊天工具。

文章始终是主舞台。词汇、译文、语法、句子理解、笔记、Ask 与导出都服务于用户读懂这篇文章，而不是要求用户学习 Claread 的内部处理方式。

## 用户、对象与边界

用户可以提交粘贴文本、网页内容或文件。每一次可长期回看的阅读经历都围绕一份 Reading Record（阅读记录）组织；它包含用户提交的材料、被确认后用于阅读的文章、逐步出现的理解信息，以及用户自己的阅读资产。

用户面对的是一篇文章和自己的阅读进度，不是 workflow、run、job、模型或向量索引。技术术语、内部状态和诊断信息不得出现在普通阅读界面。

## 核心体验闭环

1. **带入材料**：用户提交一段文本、链接或文件。
2. **确认阅读内容（仅必要时）**：当系统无法安全判断文章边界、顺序或适读性时，用户确认将要进入阅读的内容。
3. **开始阅读**：一旦正文准备妥当，用户即可开始阅读，不必等待所有理解信息完成。
4. **逐步读懂**：译文、词汇、语法和句子理解在不打断阅读的前提下持续出现。
5. **追问与沉淀**：用户从词、句、段或本文发起 Ask，保存笔记、词汇和经确认的补充内容，并在之后回看。

## Agentic Orchestration 的用户体验原则

### 阅读优先，状态可感知但不表演

文章状态使用用户友好的描述：“解析中”“解析完成”“等待继续”“需要确认”“解析遇到问题”。阅读页的状态 badge 只给出一句总览；详细说明、可追溯记录与后续操作收纳在更多菜单的“文章状态”二级界面。

不得用顶部 alert、连续 toast、自动展开面板、后台任务时间线或技术进度条打断阅读。理解信息应安静地在原文附近逐步补充，不能抢滚动位置、重排正在阅读的正文或制造“AI 正在工作”的表演。

### 用户介入只发生在真正需要决定时

短文的“确认阅读内容”默认提供全文预览。长文或多页 PDF 不要求用户重新阅读整份文件；当确有高影响处理风险时，输入流程提供结构概览、风险点和按需的完整预览。

只有高影响风险点必须被逐一查看后才可确认；普通提示不阻塞。确认发生在输入流程，确认后的阅读内容才进入 Reader。阅读过程中需要继续处理、重试或选择下一步时，用户从“文章状态”进入确认 dialog；关闭 dialog 后，该事项仍可在二级菜单中追溯。

### Ask 是当前文章的侧边助手

Ask 默认从用户正在看的内容发起：有选区时讨论当前词句或段落；没有选区时讨论本文。右侧 sidecar 必须持续显示当前范围，并允许用户在“这句话 / 这一段 / 本文”之间明确切换。

Ask 不提供 Reader 内的无上下文全局聊天入口，不直接改写文章原文。涉及原文的回答应能回到文章位置；用户确认后才可作为 Ask Supplement 加入当前阅读页。文章引用尚未准备好时，Ask 可以继续服务阅读，但不得伪造引用或把未完成状态显示成页面故障。

### 阅读设置

用户可调整阅读模式、字体、字号和外观。外观偏好为跟随系统、浅色或深色；实际阅读界面只呈现浅色或深色两种主题。设置调节阅读舒适度，不能重新定义阅读模式或干扰文章状态。

## 过渡期产品边界

新的 Reading Record / Agentic orchestration 是所有新增 Web UI 的默认承载路径。旧 AI Workflow 在新链路达到既定稳定性、测试与切换门槛前，只作为受控回退存在。

PRODUCT.md 不复制路由、DTO、状态枚举或切换门槛；这些事实由 docs/architecture/reader-orchestration.md 及其模块合同维护。旧 AI Workflow 代码移除并完成切换后，必须更新本文件：删除本节的过渡表述，并将新链路描述为稳定产品状态。

## 非目标

- 不把 Reader 做成 SaaS 后台、可拼装控制台、Word/WPS 式编辑器或 NotebookLM 式多资料工作台。
- 不把 AI chat 放在文章中心，不让右侧区域成为聊天记录或批注仓库。
- 不让解析的内部过程、失败码、模型、token、provider 或原始诊断侵入普通用户界面。
- 不以学习打卡、排行榜、连续天数或生词本数量替代真正的阅读理解。
