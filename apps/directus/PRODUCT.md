# Product

## Register

product

## Users

`Claread Console` 的核心用户不是 Claread 终端用户，而是 Claread 内部开发人员与开发 Agent。

他们使用这个平台时，处在以下几类工作情境中：

- 排查一次解析链路为什么产出了异常结果
- 判断一次 workflow / prompt / few-shot / RAG / normalize / 派生层是否合理
- 联动查看记录、结果、任务、事件、usage、debug snapshot 与派生状态
- 进行内部治理操作，例如 few-shot / RAG / workflow eval / metadata 检查

这些用户不是来“消费内容”的，也不是来“感受品牌”的。他们需要的是高信息密度但低认知负担的控制面，能快速定位异常、确认状态、下钻证据，并在必要时执行下一步内部操作。

## Product Purpose

`Claread Console` 是 Claread 的内部控制面，默认运行在 Directus Data Studio 之上。

它的职责不是承载 Claread 业务核心，也不是复刻用户端阅读体验，而是为内部开发和治理提供一个清晰、可靠、可联动的数据观察与诊断工作台。

它要解决的问题包括：

- 把多张业务表、多条任务链路和多类调试证据组织成可检查的控制面
- 让研发能够快速判断一次 run 是否完整、异常在哪里、下一步该看哪层证据
- 让 observability、workflow eval、RAG / few-shot 治理等内部能力拥有稳定工作台
- 在不把业务逻辑塞进 Directus 的前提下，提供足够强的可视化、检索、诊断和轻量操作能力

成功的 `Claread Console` 不在于“看起来像一个产品首页”，而在于：面对一条真实异常记录时，研发能够更快定位原因、减少来回查表与读 JSON 的成本，并把关键判断建立在证据链之上。

## Brand Personality

冷静、精准、证据导向。

`Claread Console` 的表达应当像一个可靠的内部诊断工具：

- 冷静：不制造情绪，不做多余装饰，不把控制面做成营销页或作品页
- 精准：每一个状态、字段、高亮和布局都服务于判断与操作
- 证据导向：结论必须能下钻到任务、事件、快照、原始结构和上下文，而不是停留在表层摘要

参考系上，它既要继承 Directus 原生数据工作台的克制和可维护性，又要在 inspector、workflow eval、RAG / few-shot editor 等深诊断场景中，具备接近 LangSmith / Sentry 的异常高亮、证据联动和层级下钻能力。

## Anti-references

- 不做营销站。
- 不把用户端 Claread 阅读器的设计语言直接搬进 Console。
- 不做通用组件无脑渲染数据的“卡片墙”。
- 不把 JSON 原样大块堆叠出来，要求用户自己消化结构。
- 不做低信息密度、重装饰、弱诊断的后台作品页。
- 不做 BI 大屏式夸张概览，不用大量伪 KPI 占据首屏。
- 不把 AI chat 式连续文本输出当成主要数据承载方式。

## Design Principles

1. 数据形态决定展示方式。表格、时间线、分段摘要、对照视图、折叠结构、句级联动，都应按数据语义选择，而不是统一套同一种容器。
2. 先给诊断结论，再给证据细节。页面首屏优先回答“现在问题大概在哪”，然后再提供任务、事件、快照和原始 JSON 的下钻路径。
3. 原生优先，自定义克制。优先使用 Directus 原生工作台能力；只有在 inspector、eval、RAG 编辑等原生能力无法承载时，才引入更强的自定义诊断界面。
4. 多表联动必须自然。记录、结果、任务、事件、usage、overview、snapshot 和原始结构不能被拆成孤立孤岛，必须能在一个工作流里连续判断。
5. 长时间排查必须低负担。用户可能连续处理多条异常记录，因此页面应强调扫描效率、锚点跳转、折叠控制、文字明确和状态稳定。
6. 原始数据是兜底，不是主视图。复杂 JSON 必须尽量先做结构化拆解、摘要和可视化，再把原始 JSON 作为最后回查层。

## Accessibility & Inclusion

`Claread Console` 面向长时间的内部分析与诊断工作，应优先保证可读性、可扫描性和低认知负担。

关键要求包括：

- 颜色不能作为唯一语义来源，异常、成功、等待、缺失等状态必须有明确文字
- 长表格、长详情和复杂 JSON 必须支持折叠、截断预览、结构化拆解和可控下钻
- 页面应支持快速跳转、稳定锚点与清晰的分区导航，减少无意义滚动
- 高风险信息应具备足够对比度与层级，但不能通过过度装饰制造视觉噪音
- 动效应轻、短、可关闭，不影响排查效率
- 复杂 JSON 的结构化拆解与可视化解析是明确要求，不应把原始对象直接当作最终展示形态
