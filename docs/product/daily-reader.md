# Daily Reader 产品说明

> **状态**: `CURRENT` | **最后验证**: 2026-08-20

Daily Reader（每日精读）是 Claread 的公开英文精读刊物。它承担内容发现、搜索与分享入口，也让未登录读者先完整体验 Claread 的阅读方法；登录只用于把文章加入个人收藏，不是阅读全文的前置条件。

## 产品边界

- 公开列表：`/daily`
- 公开详情：`/daily/{articleId}`
- 未登录读者可阅读完整正文、段落导读、译文与文末解析。
- 登录用户可在原页面收藏或取消收藏；未登录收藏会先登录，再回到同一篇文章自动完成收藏。
- Daily Reader 使用独立固定 workflow，不接入用户提交内容的 Reader orchestration planner。
- 当前不包含阅读进度、用户高亮/笔记、Console UI 或自动发布。

## 每日生产与选题

生产链按“发现 → 抽取/清洗 → 候选评分 → 内容生成 → 质量审核 → 草稿日审”运行：

1. 从 Guardian、BBC、NPR 等已登记来源发现候选。
2. 在进入模型前清理发布标记、外链徽标、版权/订阅尾注和 transcript 噪声；命中 transcript 红线的文章直接拒收。
3. 先用启发式过滤，再让最多 10 篇候选进入模型评分。最终排序以内容分为第一键，合格封面只用于破同分。
4. 每日输出按评分顺序尝试；来源与话题额度只由成功产出的文章占用，失败或中止的候选不阻塞同话题的后继候选。同一来源每天最多 2 篇，同一组归一化话题标签最多 1 篇。
5. 默认生成最多 3 篇 draft；人工可在日审队列中选择 1-N 篇发布。

候选评分当前只使用正文前 3000 字符做选文阶段的粗评；workflow 随后以全文重新判断 CEFR 难度，并让下游解析按终档适配。这是有意的成本边界，不把粗评难度当作最终成品难度。

## 内容解析

原文先从抓取块整理为适合阅读的 reading units，而不是机械保留网页换行。每篇文章生成以下层次：

- 正文：清理后的英文 reading units、标题/来源/日期/难度与图片。
- 词句：按难度选择的词汇、短语与语境表达；同一表达跨段去重。
- 段落：中文导读问题、微摘要和段译；短过渡段不强制补注解。
- 全文：中文标题、副标题与标签、文章要点、关键表达、写作借鉴、长难句、讨论问题。

差异化目前按 CEFR 难度，而不是按“新闻/评论/访谈”等文章类型分叉 workflow。系统会用全文二次定级，并分别调整选词、段落导读、长难句、讨论问题和语义审核标准。话题标签用于选题多样性，不用于选择另一套解析器。

## 质量闭环

- 确定性闸门负责脏数据、覆盖、去重、译文对齐和结构红线。
- 语义 review 使用文章最终难度检查内容价值、密度和可理解性。
- 未通过时最多执行一次定向 refinement；仍不满足红线则中止，不发布低质量结果。
- 高亮按 6 个 reading units 一批、最多 2 批并发；文章 workflow 最多 2 篇并发，成功结果仍按原评分顺序输出。
- 每个 agent 的 token usage 和总量会写入使用快照；真实金额、延迟和生产分布只能通过真实 provider 运行确认。

## Web 阅读体验

详情页使用独立的刊物式浅色 surface：中文标题优先，英文原题作为 deck，正文保持约 680px 行宽；词汇类别用实线/点线/双线区分，段落注解在桌面进入边注、移动端回到正文流。

“浏览 / 学习”切换只改变学习内容的默认展开状态：学习模式默认展开导读和译文，读者仍可逐项关闭；选择保存在本地。正文和学习内容本身不因模式而丢失。

专项视觉与交互契约见 `../../apps/web/docs/design/surface-daily-reader.md`，后端与运维事实见 `../../services/api/docs/daily-reader.md`。

## 当前验收边界

截至 2026-08-20，组合 checkpoint 已通过 Daily API、离线 eval、Web 单测、类型检查、定向 ESLint、生产构建和 390/1440 浏览器回归。以下项目仍是上线前 Owner 验收，不得用离线结果替代：

- A-5 模型路由调整后的真实 provider workflow 评测与成本/延迟采样。
- 每日 pipeline 连续 3 天自动运行并完成日审发布。
- 生产 CDN/字体/封面配置与真实网络性能。
- 独立量化 Nielsen 复评；Impeccable 的 `SHIP` 结论只表示当前实现没有阻断级问题。
